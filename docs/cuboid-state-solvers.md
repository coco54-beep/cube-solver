# 长方体状态求解与延伸机构

## 已接入

| 型号 | 当前机构与求解 |
|---|---|
| 2×2×3、3×3×2、3×3×4 | 保留逐面颜色录入；物理面片置换分阶段查表求解 |
| 2×2×4 | 二阶核心、独立外层延伸件；核心求解后处理外层 |
| 3×3×5 | 三阶核心、独立外层延伸件；单色核心棱的隐藏身份按等价块处理 |
| 4×4×6 | 四阶核心、8 个带延伸的中心、24 个独立外层件；核心降阶后处理三个外层轨道 |
| 2×3×4 | 2×2×3 核心和独立延伸；采用完整外层总能转动的标准版本 |
| 1×3×3 Super Floppy | 沿用已有专用状态求解 |
| 迷彩三阶、4×4×2 | 沿用各自绑块模型；按合法动作进行限时状态搜索 |

以上求解路径均可在清除打乱记录后工作。仍保留已校验的历史逆序作为快速路径，但手动状态不会依赖它。

## 延伸机构

`cube/extended_cuboid.py` 将内部核心、固定延伸中心、自由延伸件分别建模。核心转动带着相邻延伸件；独立外层必须先形成完整平面才能转动。面片绑定实体块，随其位置和朝向移动，露出的无贴纸面保持为黑色塑料。

六视图匹配同时检查核心占位、实体重叠、延伸件与核心朝向的一致性；观察网格仍只用于采样。新型号状态及草稿有版本标记，旧的大网格机构状态不会被套进新机构。

机构参考：[Jaap 4×4×6](https://www.jaapsch.net/puzzles/cube446.htm)、[Jaap 2×3×4](https://www.jaapsch.net/puzzles/cube234.htm)。固定长方体的短稳定子参考其 [2×2×3](https://www.jaapsch.net/puzzles/cube223.htm)、[3×3×4](https://www.jaapsch.net/puzzles/cube334.htm) 数学公式，并在本模型的面片置换上重新校验。

## 手机上的计算和内存

- 求解表在开发电脑生成，手机直接读取，不现场构造置换群。
- 延伸件的复合动作记录真实阶数；求解表与动作库使用摘要校验，防止版本错配。
- 迷彩和 4×4×2 使用四块、五块抽象距离表，以及末段状态表；五块距离用半字节保存。
- 距离表以二进制块加载，不转成包含大量数值的 JSON 对象。前向候选最多 6,000 条，深度搜索的去重表最多 50,000 条，不按打乱深度无限堆积状态。
- 复杂迷彩、4×4×2 的单次搜索预算为 45 秒，可取消；超时保留输入，不判为数学无解。它们尚不能保证任意深状态都在手机预算内完成。
- 核心复用现有二阶段/四阶降阶求解器。输出追求合法可执行，目前不保证最短解；4×4×6 的等价核心修正可能使步数较长。

## 验证边界

每个返回解都在原始输入模型上逐步检查合法转动并完整回放，只有最终外形和颜色都还原才接受。近期桌面记录见 `artifacts/cuboid-solvers/state-replay.json`：固定长方体及四款延伸型号各检查两个 40 步软件状态；延伸型号先经六视图重新匹配并清除历史，再求解；另检查了迷彩、4×4×2 和取消。记录中 16 个求解状态均完成回放。

这些是软件模型状态检查，不能替代独立实物对照；未进行手机运行、APK 打包或完整测试套件。难状态搜索仍可能超时，例如桌面曾有 4×4×2 的 25 步打乱达到 45 秒预算。

## 重新生成

- `tools/build_cuboid_phases.py`：三个固定型号的阶段表。
- `tools/build_cuboid_extensions.py`：延伸动作及阶段表。2×3×4、3×3×5、4×4×6 使用 `--depth 1 --residuals 12`；2×2×4 使用默认参数。
- `tools/build_cuboid_patterns.py`：迷彩、4×4×2 的剪枝表与末段表。仅开发时需要 NumPy。

生成的 `solver/data/*.bin` 已由现有 APK 文件规则包含。
