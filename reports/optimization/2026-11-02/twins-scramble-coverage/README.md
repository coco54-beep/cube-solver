- `controls-tests.xml`：7项通过，含真实新页面打乱／撤销、失败保留模型以及旧存档后端不串用。
- `final-service-tests.xml`：4项通过，含后台 `SolveService` 的新求解路由、源状态不变及返回动作回放。

这是 **pCubes 平面切割与倒角外壳的几何近似**，不是对实物曲面和内轨的尺寸认证。新模型没有把旧 CAD 同心球面继续伪装为可独立交换机构。原图纸外壳保留在旧状态实现和参考文件中，不额外新增目录型号。当前解法不是最短解，深度交织的手动拧动仍可能复形超时，未承诺任意状态全覆盖；安卓真机未验收。

## 以下为修正前的定位记录

第一轮 `coverage.json` 只检查十个随机种子、各30步后所有192个色面是否曾更换颜色，未发现固定颜色槽位。这不足以回答相邻小块能否独立打散；不能将该结果解释为图中同色仅是偶然。

进一步检查 `cube/twins_cad_reduced.py::reduction`，当前20个常规生成动作保留48对色面间的等变配对。每对在初始状态同色，且每个动作都将一对映射为关系中的另一对，因此任意长度的当前常规打乱都无法打破同色关系。它们是不同刚体，并非误把两个色面当成同一块。

截图可能对应每面以下内区配对（面0示例，坐标来自原始多边形均值）：

- 8 / 10：(-0.385,1,-0.385) / (-0.287,1,-0.287)
- 9 / 11：(0.385,1,-0.385) / (0.287,1,-0.287)
- 22 / 20：(-0.385,1,0.385) / (-0.287,1,0.287)
- 23 / 21：(0.385,1,0.385) / (0.287,1,0.287)

红点为屏幕标注，未逐像素还原相机姿态，故没有宣称截图四个点精确对应以上编号；检测覆盖全部配对。

`pair-invariant.json` 保存结论与形变后缀的三个样本（seed 0/1/5，30步，jumble=True）。三个样本48对对应刚体的姿态均仍一致：当前后缀也没有将这些对拆散。此处形变后缀只做了样本检查，不是任意形变序列的证明。

当前求解器将192字段约化为144字段，并对这些配对强制同色。若后续找到实物和整块几何均合法、能拆散它们的动作，必须同时扩展打乱和求解群、更新约化及缓存指纹；不能只给其中一个色面随机换色，也不能只提高打乱步数。

本轮确认的是软件打乱子群的限制。尚未证明实物是否允许拆散所有这些配对，未开放未经核对的动作，未修改求解表。
