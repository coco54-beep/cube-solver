# 1.2.29 求解内存检查

## 已修复的问题

安卓模拟器复现十三阶五魔方退出。`dumpsys activity exit-info` 记录
`LOW_MEMORY`，退出时 RSS 约 0.88GB、PSS 约 1.1GB。
这确认了模拟器上的退出原因；不能证明用户手机的退出一定是同一原因。

共用中心公式搜索的主要问题：

- 所有内层候选的正向、反向置换缓存未限制数量。
- 待处理候选保存完整 Python 整数元组，间接保留大量装箱索引。
- 一次生成整张候选列表，给高阶增加临时开销。

现在缓存受约 8MiB 的估算预算限制，待处理置换使用 16/32 位整数数组，候选
逐个生成，保持搜索顺序和完整候选集合。其他使用该搜索器的异形也得到修复。

五魔方 4～13 阶另外预置了保护已解核心的中心公式，随原有资源包发布；生成时
逐条校验三循环、核心和已解轨道保持不动。模型指纹或数据不匹配时仍回退运行时
搜索，返回的解仍经过完整回放检查。

二十面体的棱翻转配对表由嵌套元组改成整数编码，保留原来的配对范围和最小
代价比较；已经正确的朝向不建搜索表，按阶数缓存限制为最近两阶。

## 测量方法

`tools/audit_solver_memory.py` 为每种魔方启动独立桌面 Python 进程，约每 50ms
读取一次 RSS。数值包含进程、模型、导入的求解表及求解临时数据，不能等同于
手机 RAM。seed 为 12345，各类型采用自身定义的随机打乱长度；所有标记通过
的结果均独立完整回放验证。未测每个阶数、每个打乱的最坏情况。
