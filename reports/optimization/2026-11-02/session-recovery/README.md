# 启动缓存恢复防循环

2026-11-02。针对旧进度损坏或不兼容时，启动反复加载、报错、闪退的问题。

## 行为

- 读取模型前写入 `last-session.restore-pending.json`，记录源文件摘要。正常恢复并经过首屏稳定期后清除。
- 上次恢复被中断且源文件未改变时，下一次启动不再解码同一份状态，直接隔离文件、进入首页。
- 损坏 JSON、未知或已删除的型号、旧格式、恢复页面失败，统一将原始文件移至同目录的 `last-session.failed-日期-随机后缀.json`，避免覆盖之前的备份。
- 对已修改的应用字段、页面草稿、视图模型和全局配色进行回滚；取消恢复回调和临时动画，返回首页。
- 临时接管 Kivy 的恢复期延迟异常，覆盖 `on_enter`、动画结束及绘制回调。恢复结束即撤销异常处理器，不全局忽略运行时错误，也不无限吞掉重复异常。
- 恢复完成前暂停自动保存。隔离文件失败时保留源文件并暂停本次自动保存，避免用半恢复状态覆盖唯一副本。
- 首页只显示一次简短恢复提示；正常缓存仍照常恢复。测试使用独立临时数据目录，未移动或覆盖用户真实进度。

`tests.xml`：86 项通过，包括 17 项新增恢复测试及已有会话、相机、输入草稿、后台恢复和已删除型号检查。

`native-results.json`：5 个独立桌面进程均通过，使用真实 CubeApp、页面切换及 Kivy 事件循环，界面尺寸 390×844：

1. JSON 文件损坏。
2. 上次恢复中断，保留相同源文件摘要的标记。
3. 损坏的页面方向对象在延迟恢复时触发异常。
4. 切屏动画后的 `on_enter` 异常注入，验证循环外延迟异常保护。
5. 正常缓存恢复且原始文件保持不变。

所有场景均继续打开三阶输入页、填色并保存；异常场景的备份保持原始字节不变。`*-notice.png` 为恢复提示，`*.png` 为返回的首页。

复现工具：`tools/audit_session_recovery_ui.py`。新增逻辑位于 `app/session_recovery.py`，由 `app/session.py` 使用。
