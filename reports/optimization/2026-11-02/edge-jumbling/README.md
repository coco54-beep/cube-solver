# 普通直升机、Rua、四叶草、紫荆花形变补充

2026-11-02，源码实现，未打包；保留原有目录分类和型号编号。

后续审计发现：普通直升机和四叶草存在完整闭合混转进入新轨道后，被当前常规配色求解器误判非法的案例。此前生成的30/100动作案例通过，只覆盖了该生成器的路径，不能说明混转状态已完整覆盖。具体合法动作、三种子复现及旧存档入口问题见 [打乱同色关系审计](../scramble-coupling-audit/README.md)。本次审计尚未修正这两个求解器。

## 机构

- 普通直升机：45个完整材料区、48个色面；Rua：75个完整材料区、72个色面。按当前外壳和切深切分全部隐藏材料，使用整块平面范围阻挡检查，支持180°及约70.5288°、109.4712°准备。
- 四叶草：沿用现有球切外观含义，即十二个棱中点球心、半径1；45个完整区域、48个色面。没有套用鼓面4-Leaf-Clover的外壳。该具体商品版本的实测半径仍未验收。
- 紫荆花：沿用现有球切模型，补203个完整区域、192个色面的球面范围检查。常规120°，准备角采用本地Bauhinia定义的 `asin(1/4)+30° = 44.4775121859°`，另提供补至120°的75.5224878141°。
- 专门核对紫荆花的“重叠转层解锁”：60°虽能改变外形，但当前模型下只剩不重叠的其他转层可转，不能冒充换瓣。44.4775°后有三条重叠轴可以转120°。打乱实际执行准备加重叠层转动，测试检查该条件。

每次转动先检查全部材料，成功后一次性提交矩阵。颜色随整块移动，阻挡及取消不改动模型。绘制裁剪独立于机构判断，不以可见色片代替实体范围。

## 接入

四款 App 新建入口改用完整刚体模型，共用既有拧动、打乱、撤销、重置、还原界面。保留初始化完整配色，不提供手工调形和填色。旧的固定槽位数学定义仍用于常规配色表与原有教程，不能用它替代实际拧动页。

求解读取当前姿态与颜色，先做形状恢复，再调用原有常规配色求解器，转换回真实角度并逐步通过原生材料闸门回放。取消和总时间预算贯穿两个阶段。不保存打乱历史作为答案。

新增四种完整状态的会话保存、检查点及恢复；同一屏幕可以切换型号。曲面显示按完整材料邻接和三维对称消除贴合内面，形变时保留暴露塑料；两份显示缓存共1,150,411字节，避免首次打开在UI线程生成曲面。无新增大型搜索表。

## 验证

- 首轮107项通过：四款转动及阻挡、保存重载、独立求解、既有七款无录入页、花瓣/双子星形变兼容性。
- 最终37项通过，见 `final-tests.xml` / `final-tests.log`：包括24例四款各3种子×30/100步状态，保存重载后无历史求解及原生逐步回放、跨面颜色保持、原子取消、缓存色面完整、检查点兼容。
- 补充紫荆花6种子×100步测试（均含44.4775°准备及重叠转层120°），全部还原；桌面总耗时约12.5～20.1秒，解法1475～1585步。只是本轮样本，并非所有状态上限或最短解承诺。
- 最终原生App四款×800×600／390×844共8页通过，见 `native-results.json`；实际目录进入、部分转角后再转另一层、返回、验证、重置和两次撤销。截图 `*-play-*.png` / `*-twist-*.png`。对应完成日志为 `native-latest.log`；外层旧的native日志属于优化前的中间运行。

## 限制

当前球切/平面模型的阻挡检查不等于制造商内部导轨及公差认证。四叶草的具体商品版本、紫荆花内部结构仍需实物对应验证。复杂交织复形或混转后超出现有常规配色群的状态可能未完成；失败保留模型，不宣称任意状态必解。安卓真机未测。

旧的固定槽位会话不会被静默改写；重新从当前目录打开这四款进入新机构。原有常规数学模型的测试与教程可以继续使用其旧定义。
