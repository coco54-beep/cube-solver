# Tangram 手动状态还原

## 还原流程

`solver/tangram.py` 保留已有可信打乱记录的快速入口。没有历史记录的状态采用独立流程：

1. 从完整实体的姿态计算无色几何占位。Extreme 先通过真实切面约束恢复标准形状；普通 Tangram 的模型合法动作保持这一几何布局。
2. 在标准布局上，用通用合法组合表恢复实体位置和颜色。表中没有具体打乱案例、录入状态或来源块的逆序记录。
3. 手动匹配可能交换同色等价块的内部编号；精确编号不属于表内群时，另按颜色约束搜索等价代表，不把编号不一致直接判为不可还原。
4. 合并相邻同层动作，从原输入克隆逐步执行真实模型的切面和实体体积检查，最后要求 `is_solved()` 成功。验证失败不返回公式，验证期间支持进度和取消。

录入界面、颜色信息和拧动规则继续沿用实际 Tangram 模型。单纯匹配出一个结构并不等于已证明可达。

## 几何搜索

`solver/tangram_geometry.py` 从模型的实体、姿态和切面预计算合法动作。Extreme 的无色形状共有 88 个候选几何位置，每个有效状态占据其中 44 个；形状搜索用整数占位编码，颜色和来源编号不参与复形。

- 深度 7 的反向形状目录包含 56,760 个状态，按需生成并复用。
- 前向搜索为不同变形程度分别保留候选，允许先增加变形再解锁后续动作。
- 搜索限额为 20 秒、60 层或 500,000 个展开形状；支持取消。目录构建也支持取消。
- 桌面测量中目录常驻约 9.6 MiB，构建峰值约 12.3 MiB；这些数字不是手机性能结论。
- 位编码仅用于已经匹配的有效实体组装，重复几何占位会直接拒绝。返回路径仍在带颜色的实体状态上执行，并最终完整回放核验。

## 通用组合表

| 型号 | 压缩资源 | 记录数 | 表示的置换数 |
| --- | --- | --- | --- |
| Tangram | `solver/data/tangram_group.bin`，1,947 字节 | 45 | 335,923,200 |
| Tangram Extreme | `solver/data/tangram_extreme_group.bin`，4,846 字节 | 104 | 45,137,758,519,296,000,000 |

组合由复形路径闭环、共轭和交换子离线生成，再用带动作长度权重的稳定子链缩短。每个导出的组合检查切面合法性、回到标准几何及其完整贴纸置换。

普通款的表来自标准几何下的全部合法基本动作；Extreme 的表来自有限半径内的合法闭环，尚没有证明涵盖任意实物状态。表的大小或置换数量不能作为完整性保证。

资源记录版本、型号，以及实体形状、切面、有限姿态和合法转角的指纹；与当前模型不符时拒绝加载。运行时只用标准库；SymPy 仅供电脑离线建表。现有 Windows 与 Android 资源规则会包含 `solver/data/*.bin`。

重新建表：

```powershell
python tools/build_tangram_tables.py tangram
python tools/build_tangram_tables.py tangram_extreme
```

建表过程产生的 `artifacts/development` 中间结果不参与应用运行。

## 核对范围

验证使用独立生成的合法打乱，再仅将六面可观察轮廓、颜色与深度交给匹配器；录入对象不含来源帧、原块编号或打乱历史。检查匹配后全部彩色世界几何相同、历史为空、求解不修改输入，并在真实模型上再次独立回放全部解法。

- 普通款：3 个 60 步案例。
- Extreme：3 个 40 步案例，另有 2 个此前复形搜索失败的 100 步案例。
- 单元检查还比较快速状态和真实模型的合法性、全部导出组合、取消、资源指纹及重复占位。
- Extreme 的实际录入与渲染回归另有 40 项。

结果见[验收报告](../reports/solver-audit/2026-10-23/tangram-state-solver.md)。测试命令：

```powershell
python -m pytest tests/test_tangram_solver.py tests/test_tangram_extreme_input.py tests/test_variant_view.py -q --tb=short
python tools/audit_tangram_solver.py
```

这些有限案例不等于任意状态的完整性证明。Extreme 的公式仍可能达到数百步，复杂手动状态及同色等价匹配仍可能达到计算限额；尚未进行手机实测或更新安装包。
