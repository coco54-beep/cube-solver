# 录入、求解与页面自检验收

本轮没有打包、安装或发布应用。当前没有连接 Android 真机，因此本报告不代表手机端验收完成。

## 修复

1. 异步 UI 自检现在真正切换 `ScreenManager.current`，由屏幕管理器发送生命周期事件，等待切换结束再检查。原先只调用进入函数，可能检查到隐藏页面、拍到前一个页面。
2. 自检改为保存当前根画布，解决 ANGLE 下读取已交换窗口缓冲区得到黑图的问题。增加可见像素比例与画面变化检查；截图失败、黑图及切换未完成均记为失败。
3. 同一录入页测试不同型号时，按型号分别命名图片，避免八款 Mixup 的截图互相覆盖。
4. 加入 Mixup 全系列、Tangram 两款、迷彩、Pentacle、Blanker、Container、镜面五魔等录入场景。
5. 真机自检工具支持指定设备，多台设备时要求选择；旧版缺少导航和图片验证的成功报告不能作为本轮通过证据。

## 检查结果

- **125 项相关测试通过，0 失败、0 跳过**，按测试名称去重。相关测试报告和校验值见 `summary.json`，没有重复运行整个仓库测试。
- **58 次可见页面检查通过**：29 个场景分别在 390×844 竖屏、800×600 横屏运行。相机实物采集没有测试。图片已重新保存、自动检查并抽查；结果见 `visible-pages/summary.json`。
- **Mixup 16 个完整控件案例通过**：八款型号各两份独立打乱观测，从空白录入页选组合，按实际按钮的旋转步长旋转，连续填色，匹配为空历史模型，经生产 `SolveService` 求解，并用模型独立执行返回动作至复原。
- **14 个新打乱可见数据案例通过**：迷彩六例（10/40/100 次合法转动、各两个种子），六款绑块各一例，Tangram/Tangram Extreme 各一例。仅保存颜色、可见边界或面片观测，再从 JSON 重建；匹配前不传入源模型帧、块身份或打乱历史。迷彩还比较了可见接缝及可转动作集合。
- Tangram Extreme 的实际逐面点击、形状方向与颜色录入测试，现已继续调用生产求解服务并执行最终回放；没有只停留在“匹配成功”。
- 非法输入、求解失败、取消、返回、外部切屏及过期回调的相关检查通过，保留已有输入。

## 范围与发现

观测 JSON 的状态重建检查与实际控件录入检查分别记录。合法转动打乱不是均匀随机状态，40 次打乱也不代表最短距离为 40 步。通过这些案例不等于任意实物状态都有快速解。

一个新的 Tangram Extreme 40 次合法转动案例在电脑上重建与求解合计约 45 秒，仍有优化空间；时间受并发测试与环境影响，不能视为手机性能。

最初新增测试中的内棱旋转按 90°探测，与实际按钮 180°步长不一致；已改为使用真实按钮步长。部分匹配超过通用按钮测试的四秒等待，匹配生产预算为八秒；测试改为等待任务正常结束后再检查实际匹配结果，没有放宽生产搜索预算。

本轮的功能修复集中在自检可信度，没有改动求解算法或宣称消除全部搜索限制。手机系统语音、文件保存、真实切后台及设备性能仍须连接真机后执行；本轮没有新增真机结果。
