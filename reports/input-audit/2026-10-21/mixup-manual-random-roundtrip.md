# Mixup 随机状态 → 手动录入 → 无记录求解检查

日期：2026-10-21。

## 结论

现有实现不能可靠完成真实Mixup的手动录入和还原。本次8款型号、每款2个随机案例，共16例：

- 4例能用现有组合、旋转、填色操作从空白完整重建；其余12例至少有一处实际几何不在可选组合及其允许录入旋转中。
- 4例完整重建中，普通444两例均成功求解并实际回放至还原；普通344两例录入匹配正确，但形状／配对还原失败。
- 为把录入限制与求解限制分开，另外12例使用完整几何、块型、内棱块体和颜色观察数据直接匹配。这12例匹配成功，但无历史的形状／配对还原均失败。此步骤是理想观察导入，不计作界面录入成功。
- 全部16例的匹配结果，其真实彩色三维面片与源随机状态完全一致；求解入口的历史长度均为0。14个失败均报告 `mixup.shape_limit`，不能据此判断魔方无解。

## 方法

运行 `tools/audit_mixup_manual_roundtrip.py`：

1. 使用生产随机生成器 `scramble_mixup`，预算6秒，随机种子211021、211022。源案例有53至136条合法操作；数量不是最短解长度或难度指标。
2. 源模型仅用作几何／颜色对照，不传给求解器。
3. 每个观察位置仅尝试现有菜单卡片及录入旋转。全部位置有对应选项时，通过公开的 `set_assembly`、`rotate_assembly`、`paint` 从空白建立完整输入，并比较所有面片与颜色。
4. 将输入数据序列化，删除原块身份、源面片编号、组合来源及方向记录；没有模型frames或打乱历史。保留输入实际表达的几何、颜色和内棱块体。
5. 调用正式输入匹配器 `match_observations`，检查结果三维彩色面与原随机案例相同，并断言匹配模型没有历史。
6. 调用生产求解器 `solve_mixup`。成功时，将返回的每一步应用于该匹配模型的克隆，检查 `is_solved()`。没有倒放源打乱步骤，也没有通过保持已知状态的快捷路径。

进一步运行实际输入页回调：

```text
python -m pytest tests/test_mixup_manual_random_input.py -q
2 passed in 17.89s
```

两例为种子211021的普通344、444。测试从空白页开始，逐个调用实际 `pick`、`select_assembly`、`rotate_assembly`、`select_color` 和 `apply`，确认录入得到新匹配模型、历史为空、面片颜色一致，再执行生产求解。

**这里的“2 passed”表示复核结果符合断言：444成功，344仍出现已知的形状恢复失败，并不表示两例都能还原。** 使用隐藏的Kivy界面自动调用控件逻辑，未进行手机人工触摸测试。

## 留存数据及待补部分

- `mixup-manual-random-roundtrip.json` 保存16例的匹配／求解状态、耗时、组合覆盖位置与失败原因。
- `mixup-manual-inputs/` 保存每例的无历史观察草稿，供后续重现。
- 组合菜单需补齐随机合法状态出现的实际朝向与局部结构，尤其普通333／334与Plus系列；简单增加同一形状重复卡片不能补齐缺失几何。
