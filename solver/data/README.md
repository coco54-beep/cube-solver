# Strong generating sequence

## Distribution policy (2026-10-23)

Six legacy files are retained in the source checkout for offline development,
but excluded from Android and Windows packages: `circle2_table.bin`,
`fused_table.bin`, `ai_cube_patterns.bin`, `burr_cube_patterns.bin`,
`cuboid_442_patterns.bin`, and `cuboid_442_endgame.bin`. Their production
replacements are documented in `docs/optional-solver-data.md`.
Run `python scripts/bundle_assets.py` to check both packaging rules.
Two-Bar, Bandaged C, Camouflage and all newer group/layout tables still ship.

## Manual-state additions (2026-10-23)

`ai_shapes.bin` / `burr_shapes.bin` contain exhaustive uncoloured rigid-layout
graphs (70 / 182070 states). `ai_group.bin` / `burr_group.bin` contain the full
root-layout colour groups. `tools/build_bandaged_reduction.py` verifies every
graph edge against that group, then physically replays every exported word.
The runtime restores the layout before colour-constrained group sifting.

`cuboid_442_orientations.bin` stores inverse parent moves for the 2421009
reachable pairs of corner-axis states; its full address space is 2187 squared.
`cuboid_442_group.bin` reaches the root-layout parity bound `(8!)^4 / 2`.
Build with `tools/build_cuboid442_shapes.py` and `tools/build_cuboid442_group.py`;
these write review candidates into `artifacts/development/`. Verified candidates
are copied to the corresponding names in `solver/data/`.

`pentacle_group.bin` is generated by `tools/build_pentacle_group.py` after free
disc-phase normalization modulo 72 degrees. Its 114-panel group has 1221
independently replayed transversals. Continuous phase correction uses the actual
central pentagon geometry, not a remembered scramble.

`tools/rebuild_mixup_transversals.py` compacts the Plus 333/334/344 root groups
with weighted Schreier transversals. It checks complete basic-orbit coverage
against the exact original group and physically verifies each word. Original
generator records remain available for inner-edge cycle construction.

`tangram_extreme_shape_patterns.bin` contains three exact projected occupancy
distance tables (6830208 states each) and three coupled-skin relations (7392
states each). Its compressed size is about 5.9 MB. Version 2 tracks both the
cap occupancy and the axis phase changed by a middle 60-degree turn. Generate with
`tools/build_tangram_shape_patterns.py`; inspect the development candidate,
then copy it to `solver/data/`. `tools/audit_tangram_shape_patterns.py` checks
every abstract edge, proves the distances by descending neighbours, and
verifies closure/connectivity of the skin relations. The data checks both
the geometry fingerprint and the actual shape-index/transition fingerprint.

`tools/audit_tangram_completeness.py` independently constructs the full legal
fixed-action group on all reachable body and panel positions in Extreme's
phase-zero fibre. It includes the other phase's edge turns by conjugation.
Exact setwise stabilizer search certifies the prepared root group; the middle
60-degree turn bijects the two fibres. The resulting complete shape orbit is
6311112192 (8*924^3), including both axis phases. Every stored strong word and
transversal is checked in that proof. No full shape atlas is bundled.

Extreme's offline group builder keeps short native generators before choosing
a basis, and keeps short redundant root loops for weighted shortening. This
avoids replacing easy turns with long reconstructed words. The resulting
runtime root table is 5037 bytes; the offline cycle library is not bundled.

All new runtime assets check the current geometry fingerprint. Their builders
use NumPy and SymPy offline; those dependencies are not needed to read the
assets or solve on a phone. Existing `bin` packaging rules include the assets.
See `docs/manual-state-solving.md` for input tests and remaining search limits.

## Other resources

`megaminx.sgs.txt` contains the SubgroupSizes and Alg records from
[cubing.js megaminx.sgs.ts](https://github.com/cubing/cubing.js/blob/main/src/cubing/search/inside/solve/puzzles/dynamic/sgs-side-events/megaminx.sgs.ts),
by the cubing.js contributors (including Tomas Rokicki). TypeScript wrapper
syntax was removed; the algorithms and stage ordering are preserved.

Upstream offers MPL-2.0 OR GPL-3.0-or-later. This GPL-3.0 project uses the latter;
the full GPL text is included at the repository root in LICENSE. The data is
bundled in Android builds, so solving needs neither Node nor a network connection.

The Python geometry, input identification, pattern database search, and
three-cycle reduction code are part of this project's source distribution.

`fto_core.bin` contains compressed stabilizer transversals generated by
`scripts/build_fto_core.py` from this project's exact FTO layer permutations.
For orders 2 and 4 the core includes both four-piece single-colour centre
orbits as well as the six four-sticker corners. Order 3 uses the corner core;
larger remaining orbits use the existing three-cycle reduction. Each record
stores a geometry fingerprint, so changed geometry falls back to rebuilding
the complete core rather than using incompatible words. The asset is bundled
through the existing `bin` extension rule in `buildozer.spec`.

`fto_cycles.bin` contains independent three-cycle words for the remaining
FTO orbits in orders 3 and 4, generated by `scripts/build_fto_cycles.py`.
The search includes opposite anchor faces to cover both centre families.
Order 3 includes its edge orbit and both centre orbits; order 4 includes
all six larger orbits. Runtime loading checks the geometry fingerprint and
falls back to the expanded search if the asset is unavailable or stale.
This avoids repeating formula discovery on a phone at solve time.

`football_cycles.bin` now contains only orders 3 (Tuttminx) and 5 (Rayminx).
`scripts/build_football_cycles.py --orders 5` rebuilds the five-order record
while preserving order 3. The order 5 geometry uses .9/.95 face-relative cut
depths and has 722 pieces / 1112 stickers. Its data contains independent
three-cycles for all 11 sixty-piece orbits plus position and even-flip
relations for the thirty central hexagon/hexagon edges. Words are generated
from this project's exact legal pentagon/hexagon layer permutations; the
solver checks both the geometry fingerprint and complete orbit coverage.
Each record also stores a solve `order`. Because piece orbits are invariant
under every legal turn, a macro only has to fix the orbits solved before it:
it may disturb the still-unsolved orbits and still survives conjugation by any
setup. The builder ranks the hardest-to-isolate orbits first and asks for a
macro that fixes only the previously solved orbits, which shortens the order 5
macros from 40 turns to at most 8 and cuts typical Rayminx solutions by about
forty percent. Order 3 macro lengths drop from 16/8 to 6/8.

`blossom_cycles.bin` contains six independent three-cycle macros for the
regular half-turn Flower Dodecahedron, generated by
`scripts/build_blossom_cycles.py`. Each eight-move word acts on only one
ten-petal orbit and fixes all edge-cap stickers and other petal orbits.
The runtime restores the thirty edge-cap orientations before reducing the
petals, checks the geometry fingerprint, and verifies the final replay.
Jumbled partial-turn states are outside this model.

`ivy_moves.bin` is an exact next-move table generated by
`scripts/build_ivy_moves.py` from this project's four Ivy corner axes.
Its 58,320-entry address space uses four base-three corner orientations
and a six-centre Lehmer permutation rank; 29,160 entries are reachable.
Breadth-first construction records a shortest move towards the goal for
each state (maximum distance eight turns). The payload includes a geometry
fingerprint and is bundled through the existing `bin` extension rule.

`scripts/compact_polyhedral_assets.py` post-processes the prepared core words.
The order 2 FTO transversals now have at most ten turns (previously 1,368);
replacements preserve their full sticker permutations. An offline radius-five
meeting search supplies the short words without adding a phone-time search.
Icosamate order 3/5 core word totals were reduced from 10,799/12,487 to
6,919/8,607 by erasing loops on the complete core permutation. These replacements
preserve all core positions and orientations; the runtime subsequently solves
the outer sixty-piece orbits. These are asset lengths, not scrambled-state
solve benchmarks.

`scripts/improve_icosahedron_relations.py` further replaces the orientation
bases with cheaper legal conjugates and closed-position face-turn relations.
It checks exact orientation vectors, prime-component isolation, equal rank
and coverage of the original basis before saving. Run it after
`compact_polyhedral_assets.py`, because compaction first shortens the raw
words that the improver then chooses between. The mod-2 basis is restricted to
weight-4/6 vectors: weight-1/2 flips span small conjugate orbits, so a basis
that uses them leaves `icosahedron_edges.bin` too sparse. Core asset totals for
orders 2/3/4/5 are now 816/2,174/270/2,222 turns; the longest words are
360/136/78/176. Individual basis vectors can change; their span and geometry
fingerprints stay unchanged. The outer-orbit reduction remains necessary.

`scripts/build_icosahedron_core.py` searches every anchor for the order 2
centre three-cycle and keeps the shortest, instead of returning the first
match. The centre macro is 64 turns rather than 69; the same word closes the
long orientation relation, so order 2 scrambled states shorten by about four
percent on average.

`icosahedron_edges.bin` is generated by
`scripts/build_icosahedron_edges.py` and holds an overcomplete set of pure
mod-2 edge-flip conjugates for orders 3 and 5. The stored orientation basis
needs about fifteen of its long words for a typical target, but conjugating
each relation by every legal turn gives a kernel set with a large null space,
so the runtime replaces that combination with a handful of conjugates found
through a small meet-in-the-middle table. Typical `orient_2` cost drops from
roughly 700-880 turns to 220-330, cutting Icosamate and Royal Icosamate
solutions by about a fifth; the outer sixty-piece orbits are unchanged. The
geometry fingerprint is checked and the runtime rebuilds the words from
`icosahedron_core.bin` when the asset is missing or stale.

`icosahedron_twists.bin` is generated by
`scripts/build_icosahedron_twists.py` and holds overcomplete mod-5 corner
twist conjugates for orders 2-5. Eleven stored relations have a coordinate sum
of zero and their conjugates keep that sum, so a long relation fixes the sum
and the sum-zero remainder is solved in a small meet-in-the-middle table of
short conjugates. Typical `orient_5` cost drops by roughly a third to a half;
combined with the edge asset, scrambled-state averages fall by about fifteen
percent (order 2), twenty-five percent (order 3), and ten percent (orders 4
and 5). Twists are bundled separately so the missing-asset fallback keeps the
stored basis.

`scripts/build_fto_cycles_short.py` also searches inverse turns and nested
commutators, retaining an existing word whenever no shorter one is found.
Order 3 orbit 0 now uses 32 turns instead of 40; the other two use 40.
Candidates fix every outside sticker and have an exact full action of order
three before they are accepted.

`drum_prism.bin` contains stabilizer rows for War Drum and five-axis
Pentahedron orders 2–5, generated by `scripts/build_drum_prism.py`.
The prism tables cover all stickers. Drum tables cover the complete
orientation core, with independent three-cycle words for every remaining
large orbit. Records include geometry fingerprints and base-point order.
Producer guards check each row's word against its exact core action.
The runtime resolves indistinguishable prism centre labels with a
colour-constrained coset search, supports cancellation, and replays the
result before returning it. No stored scramble is used. The existing
Android `bin` rule includes this file. UI, random-state and phone tests
have not been run for these two families.


## Requested expansion (2026-10-23 / 24)

The sixteen `*_expanded_group.bin` assets for the new fixed-slot puzzles use
full sticker actions and geometry fingerprints. Rediminx reuses the verified
Starminx I mechanism asset instead of duplicating it.

`{i,l,t,x,tri,temple,cross}_cube_extensions.bin` stores legal core-preserving
macros; the matching `*_extension_group.bin` stores compact stabilizer words.
Their complete free-extension group order is `(4*k)!**2 / 2`, where `k` is
the number of extensions. Generation verifies every exported word. These are
state solvers and do not depend on saved scramble histories.

`master_brilic_cycles.bin`, generated by `tools/build_master_brilic.py`, stores
three isolated three-cycles for its three sixty-piece extra orbits. Every
word is verified on all 360 facets; transport covers every ordered triple.
The ordinary Megaminx core is restored first. No giant Brilic group table is
required. These small active assets are included by the existing bin rules;
none of the retired large distance tables has been restored.

## Complete small bandages (2026-10-24)

`tools/build_bandaged_reduction.py two_bar_cube bandaged_c bicube` exhausts
the uncoloured rigid-layout graphs, verifies every directed legal edge,
then exports and replays stabilizer words against the full bandaged engine.
The `(layouts, directed edges, root colour-group order)` records are:

- Two-Bar: `(4, 36, 416179814400)`.
- Bandaged C: `(25, 135, 111974400)`.
- BiCube: `(440, 1896, 2520)`.

The six `two_bar`, `bandaged_c`, `bicube` shape/group files total 9502 bytes.
Normal manual-state dispatch uses them without time, depth or node cutoffs.
It first aligns fixed centre colours for 3x3 global holdings, then restores
the uncoloured layout and matches the root colour group. Every returned
word is replayed with actual bandage constraints. Historical
`twobar_table.bin` and `bandaged_c_table.bin` remain for development but
are excluded from production bundles by `scripts/bundle_assets.py`.

## Camouflage octant shortcut (2026-10-24)

Three active offline assets add 683,891 bytes:

- `camouflage_3_octants.bin`: 2,295 compiled corner-preserving physical
  macros from 68,040 projected half-cube setups (596,434 bytes).
- `camouflage_3_corners.bin`: verified corner-group transversals for order
  3,674,160 (1,439 bytes).
- `camouflage_3_quotient_patterns.bin`: fifteen relaxed exact macro-distance
  projections, 641,520 decoded distance bytes (86,018 bytes on disk).

The builders are `tools/build_camouflage_octants.py` and then
`tools/build_camouflage_quotient_patterns.py`. Files have model fingerprints;
runtime only reads them. The fast macro search is bounded and nonoptimal;
its misses continue the original complete physical search. Existing active
Camouflage pattern/endgame data remain necessary for that fallback.
The unsuccessful anchor-pattern experiment stays in `artifacts/development/`
and is not a production asset. All eight retired table exclusions remain.

## MF8 Bauhinia regular 120-degree mode (2026-10-27)

`mf8_bauhinia_minx_cycles.bin` is generated by `tools/build_rex_cycles.py`.
It contains four staged geometric cycles and a 12-move pair of edge flips,
with the complete ordered-triple transport coverage for the four regular
piece orbits. It is about 296 bytes; there is no large state-distance table.
The solver reads entered colours, checks even permutations and edge-flip
parity, preserves completed stages and verifies the full returned replay.
This certifies the regular aligned-state subgroup, not arbitrary physical
jumbling configurations or inner filler-piece blocking.

## AJ 4-Layer Curvy Dinominx (2026-10-27)

`aj_curvy_dinominx_4_cycles.bin` is generated by
`tools/build_curvy_dinominx.py`. Its 248 bytes hold a four-move edge cycle,
an eight-move wing cycle and a twelve-move double-edge flip, bound to the
two-depth spherical geometry. The builder exhaustively verifies all 8120
and 68440 directed triples and the runtime reaches all 435 edge pairs.
The independent solver first restores the forty fixed-position cap
orientations, then ordinary edges, paired flips and wings. It replays
the complete result against the entered colours and never needs a scramble
witness. No full expanded-group or distance table is added for this model.

## Curvy Copter spherical profile (2026-10-27)

`curvy_copter_colour_group.bin` (10349 bytes) contains 456 certified
transversals for 36 guarded, closed-shape physical words. Rebuild with
`tools/build_copter_colour_group.py`. The file binds the sphere-cut geometry,
positive-volume material cells, all physical macro words and their actions.
Runtime uses no SymPy and reads no scramble witness. This file finishes the
colour action after shape recovery; it is not a complete shape database or a
certificate for a particular manufacturer's internal track profile.

## Retained planar twelve-axis research model (2026-10-27)

`crazy_comet_colour_group.bin` (25186 bytes) holds 852 certified
transversals for 36 closed-shape physical words on 132 panels. Rebuild with
`tools/build_comet_colour_group.py`. Every table word is independently
replayed and every stabilizer order is certified offline; the runtime
checks both geometry and source-cell fingerprints and needs no SymPy.
The initial Crazy Comet identification was rejected by the user; the public
kind is now `planar_rhombic_12`. The old asset and module names are retained
to preserve saves; this is not certification for the requested LanLan model.
The table includes closed jumbling exchanges and solves entered colours,
not a stored inverse scramble. It does not certify a complete search over
arbitrary protruding shapes. The planar cut depth is a research parameter,
not a verified match to the reference photograph or manufacturer's dimensions.

# Starminx I: face-turning reduction

`starminx_i_edges.bin` stores a verified quotient on 30 oriented edges and
12 central pentagons (72 slots), plus a pure 18-move three-petal cycle. The
runtime restores this core before handling the independent 60-petal orbit.
`starminx_i_expanded_group.bin` is retained for offline comparison and teaching
tool generation but excluded from installation resources. Rediminx has its
own `rediminx_expanded_group.bin`; it no longer shares Starminx I's data.
# Mirror Camouflage and ordinary Floppy

`mirror_camouflage_3_{patterns,endgame,octants,corners,quotient_patterns}.bin`
are independent assets for the offset silver mechanism, generated by
`tools/build_mirror_camouflage.py`. The macro catalogue uses the three sides
opposite its large bonded corner, not the ordinary Camouflage's fixed axes.
Ordinary `floppy_133` needs no file: its 192 states are searched completely
with shortest half-turn answers. `cuboid_133` remains Super Floppy.
