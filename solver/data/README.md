# Strong generating sequence

`megaminx.sgs.txt` contains the SubgroupSizes and Alg records from
[cubing.js megaminx.sgs.ts](https://github.com/cubing/cubing.js/blob/main/src/cubing/search/inside/solve/puzzles/dynamic/sgs-side-events/megaminx.sgs.ts),
by the cubing.js contributors (including Tomas Rokicki). TypeScript wrapper
syntax was removed; the algorithms and stage ordering are preserved.

Upstream offers MPL-2.0 OR GPL-3.0-or-later. This GPL-3.0 project uses the latter;
the full GPL text is included at the repository root in LICENSE. The data is
bundled in Android builds, so solving needs neither Node nor a network connection.

The Python geometry, input identification, pattern database search, and
three-cycle reduction code are part of this project's source distribution.

`fto_core.bin` contains compressed stabilizer transversals generated by
`scripts/build_fto_core.py` from this project's exact FTO layer permutations.
For orders 2 and 4 the core includes both four-piece single-colour centre
orbits as well as the six four-sticker corners. Order 3 uses the corner core;
larger remaining orbits use the existing three-cycle reduction. Each record
stores a geometry fingerprint, so changed geometry falls back to rebuilding
the complete core rather than using incompatible words. The asset is bundled
through the existing `bin` extension rule in `buildozer.spec`.

`fto_cycles.bin` contains independent three-cycle words for the remaining
FTO orbits in orders 3 and 4, generated by `scripts/build_fto_cycles.py`.
The search includes opposite anchor faces to cover both centre families.
Order 3 includes its edge orbit and both centre orbits; order 4 includes
all six larger orbits. Runtime loading checks the geometry fingerprint and
falls back to the expanded search if the asset is unavailable or stale.
This avoids repeating formula discovery on a phone at solve time.

`football_cycles.bin` now contains only orders 3 (Tuttminx) and 5 (Rayminx).
`scripts/build_football_cycles.py --orders 5` rebuilds the five-order record
while preserving order 3. The order 5 geometry uses .9/.95 face-relative cut
depths and has 722 pieces / 1112 stickers. Its data contains independent
three-cycles for all 11 sixty-piece orbits plus position and even-flip
relations for the thirty central hexagon/hexagon edges. Words are generated
from this project's exact legal pentagon/hexagon layer permutations; the
solver checks both the geometry fingerprint and complete orbit coverage.
Each record also stores a solve `order`. Because piece orbits are invariant
under every legal turn, a macro only has to fix the orbits solved before it:
it may disturb the still-unsolved orbits and still survives conjugation by any
setup. The builder ranks the hardest-to-isolate orbits first and asks for a
macro that fixes only the previously solved orbits, which shortens the order 5
macros from 40 turns to at most 8 and cuts typical Rayminx solutions by about
forty percent. Order 3 macro lengths drop from 16/8 to 6/8.

`blossom_cycles.bin` contains six independent three-cycle macros for the
regular half-turn Flower Dodecahedron, generated by
`scripts/build_blossom_cycles.py`. Each eight-move word acts on only one
ten-petal orbit and fixes all edge-cap stickers and other petal orbits.
The runtime restores the thirty edge-cap orientations before reducing the
petals, checks the geometry fingerprint, and verifies the final replay.
Jumbled partial-turn states are outside this model.

`ivy_moves.bin` is an exact next-move table generated by
`scripts/build_ivy_moves.py` from this project's four Ivy corner axes.
Its 58,320-entry address space uses four base-three corner orientations
and a six-centre Lehmer permutation rank; 29,160 entries are reachable.
Breadth-first construction records a shortest move towards the goal for
each state (maximum distance eight turns). The payload includes a geometry
fingerprint and is bundled through the existing `bin` extension rule.

`scripts/compact_polyhedral_assets.py` post-processes the prepared core words.
The order 2 FTO transversals now have at most ten turns (previously 1,368);
replacements preserve their full sticker permutations. An offline radius-five
meeting search supplies the short words without adding a phone-time search.
Icosamate order 3/5 core word totals were reduced from 10,799/12,487 to
6,919/8,607 by erasing loops on the complete core permutation. These replacements
preserve all core positions and orientations; the runtime subsequently solves
the outer sixty-piece orbits. These are asset lengths, not scrambled-state
solve benchmarks.

`scripts/improve_icosahedron_relations.py` further replaces the orientation
bases with cheaper legal conjugates and closed-position face-turn relations.
It checks exact orientation vectors, prime-component isolation, equal rank
and coverage of the original basis before saving. Run it after
`compact_polyhedral_assets.py`, because compaction first shortens the raw
words that the improver then chooses between. The mod-2 basis is restricted to
weight-4/6 vectors: weight-1/2 flips span small conjugate orbits, so a basis
that uses them leaves `icosahedron_edges.bin` too sparse. Core asset totals for
orders 2/3/4/5 are now 816/2,174/270/2,222 turns; the longest words are
360/136/78/176. Individual basis vectors can change; their span and geometry
fingerprints stay unchanged. The outer-orbit reduction remains necessary.

`scripts/build_icosahedron_core.py` searches every anchor for the order 2
centre three-cycle and keeps the shortest, instead of returning the first
match. The centre macro is 64 turns rather than 69; the same word closes the
long orientation relation, so order 2 scrambled states shorten by about four
percent on average.

`icosahedron_edges.bin` is generated by
`scripts/build_icosahedron_edges.py` and holds an overcomplete set of pure
mod-2 edge-flip conjugates for orders 3 and 5. The stored orientation basis
needs about fifteen of its long words for a typical target, but conjugating
each relation by every legal turn gives a kernel set with a large null space,
so the runtime replaces that combination with a handful of conjugates found
through a small meet-in-the-middle table. Typical `orient_2` cost drops from
roughly 700-880 turns to 220-330, cutting Icosamate and Royal Icosamate
solutions by about a fifth; the outer sixty-piece orbits are unchanged. The
geometry fingerprint is checked and the runtime rebuilds the words from
`icosahedron_core.bin` when the asset is missing or stale.

`icosahedron_twists.bin` is generated by
`scripts/build_icosahedron_twists.py` and holds overcomplete mod-5 corner
twist conjugates for orders 2-5. Eleven stored relations have a coordinate sum
of zero and their conjugates keep that sum, so a long relation fixes the sum
and the sum-zero remainder is solved in a small meet-in-the-middle table of
short conjugates. Typical `orient_5` cost drops by roughly a third to a half;
combined with the edge asset, scrambled-state averages fall by about fifteen
percent (order 2), twenty-five percent (order 3), and ten percent (orders 4
and 5). Twists are bundled separately so the missing-asset fallback keeps the
stored basis.

`scripts/build_fto_cycles_short.py` also searches inverse turns and nested
commutators, retaining an existing word whenever no shorter one is found.
Order 3 orbit 0 now uses 32 turns instead of 40; the other two use 40.
Candidates fix every outside sticker and have an exact full action of order
three before they are accepted.

`drum_prism.bin` contains stabilizer rows for War Drum and five-axis
Pentahedron orders 2–5, generated by `scripts/build_drum_prism.py`.
The prism tables cover all stickers. Drum tables cover the complete
orientation core, with independent three-cycle words for every remaining
large orbit. Records include geometry fingerprints and base-point order.
Producer guards check each row's word against its exact core action.
The runtime resolves indistinguishable prism centre labels with a
colour-constrained coset search, supports cancellation, and replays the
result before returning it. No stored scramble is used. The existing
Android `bin` rule includes this file. UI, random-state and phone tests
have not been run for these two families.
