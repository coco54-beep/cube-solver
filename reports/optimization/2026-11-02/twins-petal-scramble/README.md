# 双子星：旧存档打乱入口与花瓣内外混色修正

2026-11-02。用户反馈花瓣内部仍像未换色，本轮发现并修正两个独立问题。没有改变目录分类，没有增加资源表，没有打包。

## 旧存档仍使用旧规则

此前 `TwinsInputScreen.make_scrambled` 根据 App 当前模型选择后端。恢复旧CAD存档后，该方法会继续调用 `cube.twins_aligned.scrambled`，因而仍保留旧同色配对限制。新建目录入口虽然正确，直接在旧页面点打乱仍不正确。

现在点击打乱统一生成 pCubes 机构状态。同类状态仍按原方式恢复；如果当前是190实体旧CAD而结果是166实体新机构，共用页面会原子地替换完整模型，同时更新 App、视图和求解状态，不把不同机构的旋转数组强塞进旧实体。

替换前的完整状态进入撤销栈，撤销可恢复原来的旧机构、姿态和颜色；失败则保留原状态与历史，不能半途切换。旧存档读取本身仍保留原状态，只有用户点击打乱才执行替换。无需先退出型号再重新选择。

## 新版也可能局部看起来未打散

旧测试检查总计48对色面能否分开，以及总计有多少对异色，不能保证每一个可见花瓣区域都打散。以100个种子、每个30组合法动作测试此前的新打乱，有21个案例至少一个面仍然四组内外片全部同色。

现在先完成原有合法打乱，再按六个面分别检查四组花瓣内外片：

- 四片内部至少两种颜色；
- 四片外部至少两种颜色；
- 至少两组内外片颜色不同。

不满足时，在有限数量的小型配色置换候选中选择追加动作，只将选中的完整合法动作在真实实体上回放。没有直接改色，没有伪造可解状态，也不把逆序答案放进模型。最后仍附加一个合法形变准备动作；上述逐面标准适用于附加形变之前的闭合配色状态，不承诺任意视角下所有相邻片都必须异色。

## 验证

- `quality.json`：100个种子全部通过六面逐项检查，桌面单例最长约0.313秒。这不是安卓耗时测量。
- `solver-tests.xml`：43项通过，包含12个逐面混色回归种子及更新后24个独立重录还原案例（6种子 × 30/100组合动作 × 闭合/形变），以及实际后台求解服务。全部通过原生完整实体规则回放，无打乱历史，源状态不变。
- `controls-tests.xml`：38项通过、12项非双子星专用情景跳过。覆盖所有共用模拟页面的撤销、打乱和失败状态；双子星额外检查旧CAD → 新机构 → 拧动页 → 返回 → 撤销旧状态 → 再次打乱，以及失败不替换原状态。
- `native/native-results.json`：800×600、390×844实际页面均通过恢复旧状态、点击打乱、切换新模型、校验与撤销恢复。截图 `native/twins-new-petals-800.png` / `390.png` 展示新配色。

保留原有求解范围：闭合配色状态可独立求解；复杂交织的手动形变仍有复形时间限制，解法非最短。模型继续采用 pCubes 平切倒角近似，不声称已经测量实物曲面和隐藏内轨。
