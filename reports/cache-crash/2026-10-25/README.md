# 录入恢复崩溃修复

报错发生在 `InputScreen.set_facelets()`：按当前阶数索引另一阶的旧颜色数据，导致 `IndexError`。只读查看现有存档可见当前型号为 Cross Cube、模型尺寸为 5，而全局最近颜色记录仍是 2×2；各阶自己的缓存同时存在。

修复内容：

- 恢复前核对六面尺寸，允许从旧存档读取有效记录；不匹配时使用当前型号/阶数的有效缓存，否则保留当前正确网格。
- 直接加载错误尺寸数据返回失败并保留原录入与撤销记录；更大或更小的网格均不再裁剪或越界。
- 全局最近记录增加所属型号/阶数标记，照片录入、拧动回写、求解提交和存档读写一起更新。
- 离开页面按该页面自己的录入归属保存，避免应用已切换阶数时把旧数据写进新阶数缓存。
- 恢复存档时阻止错误尺寸的页面数据在进入页面后重新覆盖正确网格；兼容旧版部分面记录及同页恢复。

验证：

- 相关回归按测试名称去重共 **98 项通过**；最新缓存专项 **16 项通过**。
- 使用原存档副本，实际通过屏幕管理器切换页面，验证二阶旧记录进入五阶、四阶专属缓存、三/四阶往返、相同阶数不同型号四个场景。
- `visible-reproduction.json` 记录原存档校验值及未改动断言。测试只读取原文件，在临时目录恢复副本；没有清空或重写原存档。
- `five-order-restored.png` 和 `three-order-input-kept.png` 已查看；截图等待两个渲染帧，避免捕获旧标题纹理。
