# 录入校验、求解和按钮状态统一检查

日期：2026-10-25。未重新打包，未进行安卓手机实测。

## 行为

| 情况 | 页面与提示 | 按钮和输入 |
| --- | --- | --- |
| 已知的录入校验失败 | 留在录入页，页内红字“输入未通过” | 保留输入和错误位置高亮，允许修改 |
| 匹配无法完成 | 留在录入页，页内说明 | 保留录入，任务结束后恢复编辑 |
| 求解准备异常 | 不进入求解页，页内“操作未完成” | 释放原待启动请求，保留输入 |
| 求解过程中失败 | 返回来源录入页，页内“求解未完成” | 保留输入，可重试或继续编辑 |
| 取消／返回 | 立即返回来源录入页 | 取消任务的应用资格，恢复动作按钮 |
| 切换其他页面 | 切屏动画开始时就使旧任务失效 | 旧进度、结果及取消操作不能将页面拉回 |

录入及从录入启动的求解错误不再使用错误弹窗。清空等确认窗口、帮助和其他专用窗口不属于错误提示。长提示自动换行、扩展消息区域，普通进度文字恢复后收回高度。

## 实现

- `ui/entry_state.py` 统一持有后台任务阶段、身份、活动状态及锁定状态。阶段限定为空闲、工作中、打乱、匹配、准备求解和求解。
- `EntryActionsMixin._job` 是兼容旧工作器的属性入口，读写同一状态对象的任务身份；不会再形成另一套状态。
- 打乱按钮删除定时轮询。异步任务开始、结束和取消通过状态事件直接改变按钮锁定；同步回调期间直接禁用按钮。整行动作控件锁定保留子按钮本来就不可撤销／重做等条件。
- 原有镜头、拧层和卡片过期检查继续生效。录入页离开时发送取消信号、使旧任务失效，且不会先短暂解锁再锁回。
- 公共反馈层保留各型号自己的校验与高亮；已知输入错误、操作异常、求解失败与取消分别标记。
- Mixup 空白输入在开始后台匹配前检查，缺块或缺色归为输入问题。匹配过程中报告的已知输入异常也不会误标为内部操作失败。
- 求解页保存独立快照，覆盖待启动取消、启动异常、重复进入、重复请求、取消后新请求、切屏开始时失效及失败回到来源页的提示。
- 服务重启会取消上一请求的独立令牌；已取消请求即使后来计算完成也报告取消，不把成功结果交作当前任务。不可及时退出的旧后台计算可能继续结束，但不会再改页面或输入。
